# j2act

Design lives in `CONTEXT.md` (glossary) and `docs/adr/` (decisions). Code style in `docs/STYLE.md`. Machine-specific notes, if any, are in `CLAUDE.local.md` (gitignored).

## Next-run orientation

- Build with the wrapper and JDK 17+: `./mvnw install` (Maven 3.9.16; the enforcer rejects older JDKs). Libraries still emit Java 11 bytecode except `j2act-spring` and `examples/counter-spring` (release 17, Spring Boot 3+). No javax anywhere.
- Spring Boot matrix: the version is `spring-boot.version` (default 3.5.x). Check other lines with `./mvnw -pl j2act-spring,examples/counter-spring clean install -Dspring-boot.version=<3.0.x|4.0.x|4.1.x>`. Don't use `@LocalServerPort` in tests: its package moved in Boot 3.0 and 4.0; `@Value("${local.server.port}")` works everywhere.
- Reactor: `j2act-codegen` (build-time generator, not shipped), `j2act-core` (runtime, zero deps, client JS in `META-INF/resources/_j2act`), `j2act-html` (generated typed tags + handwritten `TagHelpers`), `j2act-router`, `j2act-processor` (build-time checks and client module `.d.ts` types for javac and ECJ, on the processor path only; the examples use it), `j2act-spring` (Boot 3+ auto-config, Java 17), `j2act-jakarta` (Jakarta EE 10 mount), `examples/counter-spring` (runnable demo + end-to-end test), `examples/counter-jakarta` (WAR for WildFly 27+). `examples/team-dashboard` is a design sketch of future APIs, not in the reactor, and does not compile.
- Never hand-edit `j2act-core/.../GlobalAttributes.java`, `j2act-core/.../j2act/web/*` (the window() facade, curated in `data/window-api.json`), `j2act-html/.../TagCreator.java` or `j2act-html/.../tags/*`: change the generator, `j2act-codegen/src/main/resources/data/overrides.json` or `window-api.json`, then `./mvnw -pl j2act-codegen compile exec:java`. A test fails when checked-in output drifts. Refresh upstream data with `-Dexec.mainClass=j2act.codegen.UpdateData`.
- Core tests drive sessions headlessly via `j2act-core/src/test/java/j2act/Harness.java`; handler ids stay stable while their element keeps rendering at the same position and die when it stops rendering; after a structural change take ids from the latest patch HTML.
- If tests fail with "Unresolved compilation problems", an IDE language server (ECJ) wrote broken classes into `target/`; run `./mvnw clean install`.
- The Spring Boot BOM is imported only in `j2act-spring` and `examples/counter-spring`, so Spring's managed versions never leak into core or the Jakarta EE modules.
- Browser checks drive headless Chrome over CDP with no dependencies (`tools/cdp.mjs`, Node 22+; set `CHROME` if Chrome is not at the Windows default path). Spring: run the demo jar on port 8089, then `node tools/browser-check.mjs`. On Windows, stop the demo before `./mvnw install`, or the locked jar makes `repackage` fail.
- Processor checks must agree across compilers: `ProcessorTest` compiles `j2act-processor/src/test/fixtures` with javac and ECJ and wants identical diagnostics; mark expected warnings with `// expect: <text>` comments. For the IDE leg, install the reactor, then `JDTLS=<unpacked jdt-language-server> JAVA=<java 21+> node tools/jdtls-check.mjs`.
- Client modules (ADR 0022): `Name.client.js` sits beside `Name.java` and reaches the classpath as a resource with the files it imports (the example poms include `src/main/java/**/*.js` and re-list `src/main/resources`, since overriding `<resources>` drops the default); the runtime serves it from `/_j2act/m/`. Core tests stand in for runtime.js with `Harness.send` (see `ClientTest`); the browser and WildFly checks drive the `Countdown`, `BrowserApis`, `SalesChart` (Chart.js) and `NoteEditor` (Quill) demos. JavaScript never gets a build step (only TypeScript does): npm packages come in as `org.mvnpm` dependencies, the runtime merges their `META-INF/importmap.json`, resolves bare names through `package.json` exports as Node does, and serves the files from `/_j2act/pkg/`, wrapping CommonJS as ES modules (`CommonJs.java`, `Packages.java`). The browser checks read every `li` on the page, so demo markup should avoid `li`.
- TypeScript examples: `examples/ts-npm` and `examples/ts-pnpm` (Spring Boot, ports 8090/8091) type-check with tsc and bundle `*.client.ts` with esbuild into `target/classes` via frontend-maven-plugin, which installs Node into `examples/*/node/` (gitignored). Run the jar, then `node tools/ts-check.mjs http://localhost:8090/` (or 8091). If a build step fails, `npm run build` or `pnpm run build` in the example folder shows the tsc/esbuild error directly.
- WildFly check: WildFly is not in the repo; unzip a 27+ release (34 is the last on Java 11), copy `examples/counter-jakarta/target/counter-jakarta.war` to `standalone/deployments/`, start `bin/standalone.sh`, then `node tools/wildfly-check.mjs`. Stop with `bin/jboss-cli.sh --connect --command=:shutdown`.
