# j2act

Design lives in `CONTEXT.md` (glossary) and `docs/adr/` (decisions). Code style in `docs/STYLE.md`. Machine-specific notes, if any, are in `CLAUDE.local.md` (gitignored).

## Next-run orientation

- Build with the wrapper on JDK 21 or 25 (CI runs both): `./mvnw install` (Maven 3.9.16; the enforcer rejects older JDKs). Libraries still emit Java 11 bytecode except `j2act-spring` and `examples/counter-spring` (release 17, Spring Boot 3+). No javax anywhere.
- Spring Boot matrix: the version is `spring-boot.version` (default 3.5.x). Check other lines with `./mvnw -pl j2act-spring,examples/counter-spring clean install -Dspring-boot.version=<3.0.x|4.0.x|4.1.x>`. Don't use `@LocalServerPort` in tests: its package moved in Boot 3.0 and 4.0; `@Value("${local.server.port}")` works everywhere.
- Reactor: `j2act-codegen` (build-time generator, not shipped), `j2act-core` (runtime, zero deps; the client runtime is TypeScript in `src/main/ts`, bundled into `META-INF/resources/_j2act/runtime.js`), `j2act-html` (generated typed tags + handwritten `TagHelpers`), `j2act-router`, `j2act-processor` (build-time checks and client module `.d.ts` types for javac and ECJ, on the processor path only; the examples use it), `j2act-spring` (Boot 3+ auto-config, Java 17), `j2act-jakarta` (Jakarta EE 10 mount), `j2act-retained-jdbc` (Retained State in the app's DataSource, ADR 0026; j2act-spring wires it optionally), `j2act-maven-plugin` (Vite and tsc for Maven builds), `examples/counter-spring` (runnable demo + end-to-end test), `examples/counter-jakarta` (WAR for WildFly 27+). `examples/team-dashboard` is a design sketch of future APIs, not in the reactor, and does not compile.
- Never hand-edit `j2act-core/.../GlobalAttributes.java`, `j2act-core/.../j2act/web/*` (the window() facade, curated in `data/window-api.json`), `j2act-html/.../TagCreator.java` or `j2act-html/.../tags/*`: change the generator, `j2act-codegen/src/main/resources/data/overrides.json` or `window-api.json`, then `./mvnw -pl j2act-codegen compile exec:java`. A test fails when checked-in output drifts. Refresh upstream data with `-Dexec.mainClass=j2act.codegen.UpdateData`.
- Client runtime (ADR 0028): edit `j2act-core/src/main/ts`, then `npm install` (once) and `npm run build` in `j2act-core`, and commit the rebuilt `runtime.js`; `RuntimeBundleTest` fails on a stale bundle, and CI rebuilds it and fails on any difference. `npm run check` type-checks and runs the Vitest unit tests (`src/test/ts`, happy-dom). Idiomorph is bundled in, so there is no `Idiomorph` global: the browser checks wait for `window.j2act`.
- Core tests drive sessions headlessly via `j2act-core/src/test/java/j2act/Harness.java`; handler ids stay stable while their element keeps rendering at the same position and die when it stops rendering; after a structural change take ids from the latest patch HTML.
- If tests fail with "Unresolved compilation problems", an IDE language server (ECJ) wrote broken classes into `target/`; run `./mvnw clean install`.
- The Spring Boot BOM is imported only in `j2act-spring` and `examples/counter-spring`, so Spring's managed versions never leak into core or the Jakarta EE modules.
- Browser checks drive headless Chrome over CDP with no dependencies (`tools/cdp.mjs`, Node 22+; set `CHROME` if Chrome is not at the Windows default path). Spring: run the demo jar on port 8089, then `node tools/browser-check.mjs`. Retained State (ADR 0026): start the jar with `--demo.idle-timeout=PT3S --demo.auto-pause=PT1S`, then `node tools/retained-check.mjs`; for checkpoints add `--demo.checkpoint-interval=PT1S` and pass `--restart "bash <script>"` (forward-slash path) whose script sleeps 3 s, force-kills the jar (`Stop-Process -Force`, so no shutdown save runs) and relaunches it detached. On Windows, stop the demo before `./mvnw install`, or the locked jar makes `repackage` fail; a demo killed just before the build can still hold it, and `-q` hides that the old jar stayed, so check the jar's timestamp when a browser check contradicts the code.
- Processor checks must agree across compilers: `ProcessorTest` compiles `j2act-processor/src/test/fixtures` with javac and ECJ and wants identical diagnostics; mark expected warnings with `// expect: <text>` comments. For the IDE leg, install the reactor, then `JDTLS=<unpacked jdt-language-server> JAVA=<java 21+> node tools/jdtls-check.mjs`.
- Client modules (ADR 0022): `Name.client.js` sits beside `Name.java` and reaches the classpath as a resource with the files it imports (the example poms include `src/main/java/**/*.js` and re-list `src/main/resources`, since overriding `<resources>` drops the default); the runtime serves it from `/_j2act/m/`. Core tests stand in for runtime.js with `Harness.send` (see `ClientTest`); the browser and WildFly checks drive the `Countdown`, `BrowserApis`, `SalesChart` (Chart.js) and `NoteEditor` (Quill) demos. JavaScript never gets a build step (only TypeScript does): npm packages come in as `org.mvnpm` dependencies, the runtime merges their `META-INF/importmap.json`, resolves bare names through `package.json` exports as Node does, and serves the files from `/_j2act/pkg/`, wrapping CommonJS as ES modules (`CommonJs.java`, `Packages.java`). The browser checks read every `li` on the page, so demo markup should avoid `li`.
- Vite (ADR 0023-0025): TypeScript, npm packages and Tailwind build with Vite through `j2act-vite` (the `@j2act/vite` npm package, linked as `file:../../j2act-vite`), onto the classpath under `META-INF/j2act/vite` with Vite's manifest. `j2act-maven-plugin` (reactor module, goals `bundle` and `typecheck`) runs it for Maven; `j2act-gradle-plugin` is its own Gradle build (Gradle 9.8.1 wrapper, Java 11 bytecode, compiled and tested on a JDK 21 toolchain that foojay downloads when missing, TestKit tests on Gradle 8.14.5 and 9.8.1) that the Gradle examples use through `includeBuild`. Both need `./mvnw install` here first; `exploded-hotswap` (`io.github.then00p`, github.com/THEN00P/exploded-hotswap) comes from Maven Central at the version in `J2ActExtension.EXPLODED_VERSION` and `j2act-gradle-plugin/build.gradle.kts`. The Maven Vite examples use the plugin with `<extensions>true</extensions>`, which Maven resolves before building anything, so they are their own build: `./mvnw -f examples install` after the root install. Examples: `ts-npm`, `ts-pnpm` (Maven, Spring, 8090/8091, `tools/ts-check.mjs`), `vite-maven-wildfly` (Maven WAR), `vite-gradle-wildfly` and `vite-gradle-spring` (own Gradle builds, port 8092); `tools/vite-check.mjs` (add `--reimport <client.ts>` for dev mode), `tools/vite-stress.mjs`, `tools/hotswap-check.mjs` (redefines an edited `HomePage` over JDWP in a WildFly started with `--debug 8787`, as an IDE's hot code replace does; needs JetBrains Runtime with `-XX:+AllowEnhancedClassRedefinition`) and `tools/jdtls-probe.mjs` (headless VS Code: `JDTLS=/tmp/jdtls JAVA=<java 21+> GRADLE_JAVA_HOME=<jdk 17>`) check them. Dev mode only runs from class folders or exploded deployments: deploy `target/exploded/*.war` (`mvn exploded-hotswap:exploded`) or `build/exploded/*.war`, not the WAR file. Kill a running example by its main class or jar (`Get-CimInstance Win32_Process -Filter "Name='java.exe'"` in PowerShell), since Git Bash has no `pkill`; without the `java.exe` filter, a `-like '*name*'` match also kills the shell that launched it. `docs/spikes/frontend-build.md` records how the design was tested in Eclipse and VS Code.
- Publishing (ADR 0029): coordinates are `io.github.then00p.j2act` until 1.0 (Java packages stay `j2act.*`, `dev.j2act.gradle`, `dev.j2act.maven`). A `v*` tag runs `.github/workflows/release.yml`, which releases the Maven modules, the Gradle plugin and `@j2act/vite`; secrets are set on the repository. To check a release without publishing, set a non-snapshot version (`versions-maven-plugin:2.22.0:set` with backups, then `:revert`) and run `-Prelease deploy` with `MAVEN_GPG_KEY`, `MAVEN_GPG_PASSPHRASE` and the `central` server in settings.xml: without `-DautoPublish=true` it stops at a validated deployment to drop in the Central Portal. Never run `-Prelease deploy` at a snapshot version: it uploads to Central's snapshot repository instead of validating. Gradle signs only with `signingInMemoryKey`; calling the `gpg` program on this machine pops up a passphrase prompt.
- WildFly check: WildFly is not in the repo; unzip a 27+ release (34 is the last on Java 11; older releases die on JDK 25 with "Setting a system-wide Policy object is not supported", so start them with `JAVA=<jdk 21>/bin/java`), copy `examples/counter-jakarta/target/counter-jakarta.war` to `standalone/deployments/`, start `bin/standalone.sh`, then `node tools/wildfly-check.mjs`. For Retained State start it with `JAVA_OPTS="-Ddemo.idle-timeout=PT3S -Ddemo.auto-pause=PT1S"`, then `node tools/retained-check.mjs http://localhost:8080/counter-jakarta/ --restart "<WildFly>/bin/jboss-cli.sh --connect --command=:reload"` (the draft has to survive the redeploy). Stop with `bin/jboss-cli.sh --connect --command=:shutdown`.
