# Keyless queries with validated runs

A query is one lambda: query(() -> users.search(filter.get(), page.get())). No key, no dependency list; every State read inside the loader is a dependency. Most components mount once per page, so naming a cache entry is ceremony TanStack needs only because JS frameworks cannot see the reads. Frameworks that went keyless (Vue computedAsync, Svelte 5 async $derived) can do it because JS is single-threaded; ones that are async-safe (Solid createResource, Angular resource, Leptos) split source from fetcher. We keep the keyless shape and make it safe across threads instead.

Validated runs. The loader runs on the executor, never on the session lane, so slow queries run in parallel and never block events. State.get() inside a loader run is legal (the one exemption from ADR 0014's foreign-read warning): each read is recorded as (State address, value) in the run's own read set, not in the session graph. On completion the result is handed to the lane, which compares every recorded value with the current one. All equal: commit the data and merge the read set into the graph. Any changed: discard, since a newer run was already triggered by that change. Optimistic concurrency, not locks; only the lane ever touches the graph (ADR 0001), and a run that read a newer value mid-flight is caught the same way. Rapid input supersedes runs, and stale results never flash.

The Query is a slot-bound primitive (ADR 0019): re-running render() returns the same Query and the loader does not re-run. It re-runs only when a State in its committed read set changes, on refetch(), or on invalidation.

Cache survives unmount. Every State has a deterministic address (component slot plus creation order), so an entry stores the addresses and values it read. A component destroyed by an if and recreated at the same slot finds its entry by slot, reads the current values at the recorded addresses, and gets a hit without running the loader when they match. Inactive entries live for gcTime and are trusted for staleTime; past staleTime they render at once and refetch in the background with no loading() flash (ADR 0007). Both are configurable per query and on the mount, inside the per-session cache bound (ADR 0003). An explicit withInvalidates always wins.

Ambient reads are tracked too. A loader run is a bound work item (ADR 0014), so pathParam(), queryParam(), auth() and Store select() work inside it, read from the session as of the run and recorded in the read set like State. A Page kept across /users/1 to /users/2 (ADR 0019) refetches because the loader read pathParam("id").

Captured locals are the user's to declare, as in React and Solid. long id = ...; query(() -> users.find(id)) captures a value computed in render(), which is not a tracked read, and the slot-bound Query ignores later lambdas, so it goes stale silently. Two forms are correct: read the input inside the loader, query(() -> users.find(selected.get().getId())), which Solid does; or name it in the key, query(() -> users.find(id)).withKey("user", id), which TanStack's queryKey does, since keys are compared every render. The runtime does not diff captured values by reflection: neither React nor Solid does, and a lambda's capture layout is not a Java guarantee. The one diagnostic, a loader that captures a non-this value without withKey, belongs to the build-time processor (ADR 0008), mirroring exhaustive-deps and solid/reactivity; there is no runtime check.

Props are tracked. A plain field read in a loader is invisible, so a parent passing a different user would leave stale data. Props are Prop<T> fields written by the with* builder (user.set(u) inside withUser) and read with get(), like Solid's reactive props. This closes the same hole for computed() and effect().

Sharing is opt-in and TanStack-shaped. withKey(parts...) takes any number of parts, e.g. withKey("users", filter.get(), page.get()), and makes the part list the cache identity across components: dedup, sharing, and prefix invalidation via withInvalidates("users") or withInvalidates("users", filter.get()). Parts need equals()/hashCode(). Reads inside a keyed loader are still tracked for refetching. Within a session one cell per key runs and holds the data; others follow it, and when it unmounts a follower inherits its data, read set and readers without refetching. A component can also call invalidate(prefix...) directly. The key must be known before running, which is why sharing cannot use address matching: two components' States live at different addresses.

Risk to prove in the first slice: the commit-time validation, since everything else leans on it.
