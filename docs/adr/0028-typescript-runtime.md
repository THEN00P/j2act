# The client runtime is TypeScript, built into a checked-in bundle

runtime.js grew past 1,200 lines in one closure, with about thirty shared variables and no tests below the browser checks. It is now TypeScript in `j2act-core/src/main/ts`, split by concern (connection, morph, events, pending, navigation, uploads, clients, web, retained), and Vite builds it in library mode into the one `runtime.js` the jar serves. Idiomorph comes from npm (0.8.0, the version that was vendored) and is bundled in, so a page loads one script and the `Idiomorph` global is gone.

**The bundle is checked in.** Building it during the Maven build would put Node into every build of j2act-core, a module with no dependencies, and into every IDE that builds it. Like the generated tag API (ADR 0021), the output is committed and checked against its sources twice. Its banner names a SHA-256 of the sources, `package-lock.json` and `vite.config.ts`, and `RuntimeBundleTest` recomputes it without Node, so an edit without a rebuild fails `./mvnw install`. CI (`.github/workflows/ci.yml`) runs `npm ci`, the type check and the unit tests, rebuilds the bundle, and fails if it differs from the committed one by a byte. It then runs the whole build on that bundle. Only editing the runtime needs Node: `npm install` once in j2act-core, then `npm run build`.

JSDoc with `// @ts-check` was the no-build alternative. It types the same code, but JSDoc for discriminated unions and classes is verbose, and splitting the file would still need native modules (one request each) or a bundler. esbuild alone would have done the bundling. Vite is the tool ADR 0023 already chose for apps, and its tests run under Vitest with the same config.

**Apps never need TypeScript.** The served file is plain JavaScript, so nothing changes for an app's own client modules: `Name.client.js` stays build-free (ADR 0022). The runtime's API, `window.j2act` (ADR 0026) and its `j2act:paused` and `j2act:resumed` events, is typed in `j2act.d.ts`. The processor writes it to `.j2act/types` next to the client types, so tsc and editors see it in projects with a package.json (ADR 0023). A plain JavaScript project can use the same types with `// @ts-check`, or ignore them.

**The protocol is typed.** `protocol.ts` lists every socket message in both directions as a discriminated union, so the runtime's dispatch is one `switch` the compiler checks. The Java side (J2Act.onMessage and the `Json.object` calls) is still written by hand; generating one side from the other can come later.

Behavior stayed the same, with three exceptions. Reconnects and upload retries back off with jitter (half of each delay is random), so pages do not all return in the same instant after a server restart. A socket closed on purpose during a remount can no longer schedule a reconnect if its close event arrives late. Per-element state lives in WeakMaps instead of expando properties.
