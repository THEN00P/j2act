# Keep unchanged children out of a parent's patch

ADR 0003 sends a dirty component's whole subtree as HTML and lets Idiomorph sort out the DOM. Measured on the counter demo, a re-render of the home page sent 8 KB, of which a few hundred bytes had changed: the page's own markup is small, but every child component rendered again and went out with it. Bandwidth is fine for one click. It is not fine for a page with a lot of quickly changing state near its root.

Blazor faces the same cascade and skips a child whose parameters did not change. We do the same. When a parent re-renders, a child keeps its element if nothing it read changed (it is not dirty), its Props equal what its parent's builders now set, and its plain fields equal last render's. The renderer then does not run the child's render() at all and writes an empty element of the child's root tag in its place, `<tr data-j2-unchanged="s7"></tr>`. Using the root's own tag keeps the placeholder legal wherever the HTML parser puts it, inside a table body included. The client swaps in a copy of the element it already shows for that anchor, so the morph finds nothing to change and leaves the live element alone. A fresh description (c() rather than a held object) that turns out unchanged is dropped unbound, and the object that rendered last keeps its handlers, its client bindings, its head and its children.

Props compare with equals(), as State writes already do, so a list a parent changes in place is not a change, which is the rule State already has. Plain fields compare the same way, with two refinements: a field holding another component's State compares by cell, and a client(...) handle by its slot. A fresh description's own primitives count too, since the kept object would go on using its own: a query's loader, a mutation's body, a query state's parameter name and parser must equal the fresh ones, lambdas comparing by class and captured values, so a constructor argument a mutation captured cannot go stale. Only a State's initial value is left out, as it matters only when the cell is created. An anonymous or local component's captured values are fields like any other. Lambdas, method references and DomContent in plain fields are new objects each render, so a child given one always renders, as in Blazor, where delegate and RenderFragment parameters always count as changed. We do not copy Blazor's stricter rule that any mutable parameter type counts as changed: every component holding an injected service or a List prop would always render, and in j2act the State and Prop equality rule already says what a change is.

The cost is a new constraint, and it is the real trade-off here: render() must be a function of what it reads through State, Props, Queries, the route and auth(), plus its fields. A component that shows an untracked value, such as a counter on a service, used to refresh whenever any ancestor re-rendered and now only when it renders itself. The demo's ProfileCard showed exactly that, and now shows a count that changes only when the card loads a profile.

A child can only be kept if the client has its last render. Each scope records whether its last render reached the client: set for every scope a sent patch or the served page rendered, cleared when its render starts and on every reconnect (patches sent into the old socket may have been lost). It stays cleared for renders that are held during a soft navigation, rendered offscreen for a preload, replaced by a loading or error boundary, or handed to a client action. Children inside pending templates and client slots always render, since the client may not have their elements in place. If the client still cannot find a kept element (client code removed it), it applies nothing and sends `resync` with the patch's anchor, and the server renders that scope again in full. `J2Act.Stats` counts both patch characters and resyncs.

ADR 0003's "no retained HTML" still holds: the server keeps a root tag name and the field values per component, not markup. Diffing inside one component is still out: hashing every element's output would cost the server more than the bytes are worth. If large components that change often need more, the candidate is reactive regions, parts of a render with their own dependencies whose patches are still HTML for Idiomorph, first as API and perhaps later inserted by a build step (BACKLOG), once a spike shows the numbers justify them.
