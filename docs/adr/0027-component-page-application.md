# What a component reaches: itself, its page, the application

A component reaches three levels, and each must read as what it is. Getting this wrong makes a call look scoped to the component when it acts far wider: `this.requestPause()` on `ComponentTag` would read as pausing that component's state when it paused the whole page.

**The component and its page are one level.** `ComponentTag` holds what the component owns, the primitives bound to its slot (`state`, `retainedState`, `query`, `computed`, `mutation`, `download`, `upload`, `effect`, `client`, `onPersisting`, `onRestored`, ADR 0019), and what its page shares: `navigate`, `invalidate`, `auth`, `pathParam`, `queryParam`, `window`, `pauseTab`. A page-level call that could be mistaken for a component-level one names its reach, as `pauseTab()` does: it pauses the browser tab, not the component. These stay methods on `this`. A component can be a page, so page-level calls on it read naturally, as React's and Vue's router hooks and Wicket's `getPage()` do. Primitives must be methods on `this` anyway: field initializers run in a constructor the app calls, so `this` is the only way j2act learns their owner.

**The application is reached with `application()`.** It returns `Application`, the deployment's j2act as components see it: what spans every page, such as `requestPause()`, which asks every connected tab to pause (ADR 0026). Host code that has the `J2Act` from its DI (a Spring bean, the Jakarta listener) calls it directly. This follows Wicket's `Component.getApplication()`, the closest Java prior art.

**There is no `session()`.** j2act's session is one page load, which Vaadin calls a `UI` and Blazor a circuit. Wicket's `getSession()` and Vaadin's `VaadinSession` mean the HTTP session shared by every tab, and that is what readers would assume. Nothing public is named session, and there is no static `current()` accessor: a static call reads as global state, while `application()` on a component reads as reached through it.
