# Portable core with Spring and Jakarta adapters on Java 11

We must run as island or standalone on both Spring Boot and Wildfly/Jakarta without owning auth/DB, while staying on a Java 11 baseline. Core stays servlet/WS-SPI agnostic using only Java 11 APIs, with thin j2act-spring and j2act-jakarta transport mounts. No vendor auth adapters: identity extraction is a user-supplied seam (one Exchange-to-AuthCtx fn on their own stack, or nothing for no-auth apps). The framework owns only enforcement points — guard checks and per-event re-checks — never identity sources. Components are host-DI-aware through a members-injector seam (Spring @Autowired, CDI @PersistenceContext, or manual): data access uses injected fields, so stacks without JPA inject nothing and the framework defines no em(). Verified on WildFly 29: CDI's injection target performs @Inject and @PersistenceContext injection into component objects, which are non-contextual instances; inject normal-scoped beans, since a @Dependent bean would be recreated for every fresh component object. Fully optional: no seam call and no guards means a public app, and the resolver is invoked lazily only when a guard or render actually reads AuthCtx, so unused auth costs nothing.

Deployment constraint: serverful UI needs sticky sessions when scaled horizontally — the dependency graph and query cache are per-server memory. Document it for island hosts: route a socket (and its session) to one node; no replication of framework state.
