# Generated tag API from HTML data

ADR 0002 planned to fork j2html. We keep j2html's API shape (typed per-element classes, children-only static factories, with/withCond/is builders, each/iff/join) but not its code or its hand-maintained HTML model. j2act-codegen, a build-time module that is never shipped, generates GlobalAttributes in core, one final class per element and TagCreator from vendored data. The output is checked in so IDEs and reviewers see real sources, and a test fails when it drifts from the generator.

Data, pinned in UpdateData: @vscode/web-custom-data for elements, attributes, descriptions and Baseline support; @mdn/browser-compat-data for deprecation and MDN links; @webref/elements for the spec's element list. That buys what j2html lacks: Javadoc with MDN descriptions and links on every element and attribute, Baseline support notes, and @Deprecated from MDN. TypeScript types were rejected as a source: lib.dom.d.ts describes DOM properties (className, htmlFor), not content attributes, and React's types describe JSX. Where the data disagrees with the HTML standard, data/overrides.json corrects it with a reason per entry (boolean autofocus and inert, valueless download and sandbox, rel on form, and attributes that would shadow withText).

Deliberate differences from j2html: no inline on* attributes (events are server handlers, ADR 0013), rawHtml is unsafeHtml (ADR 0008), no attrs("#id.cls") shorthand (params stay children only, ADR 0005), obsolete elements and attributes are not generated, and non-element helpers live in handwritten TagHelpers. j2html is a test-only dependency: J2htmlCompatibilityTest checks every j2html 1.6.0 factory and builder exists here under the same name, apart from a listed exclusion set with reasons, so migrating stays a change of imports. SpecCoverageTest checks every live element of the HTML spec is generated.
